fix(ui): format the Agent table's cost column; readable primary button

Three findings from a front-end audit, two of them real defects.

The Agent table printed a raw float in its 参考费用 column:
8.171517142, 0.17028839999999998. The Model and project tables show $8.17
for the same semantic column, because they call moneyCell; fillTable only
reached moneyCell for a NULL value, so a priced cell was copied through as
text. fillTable now takes a moneyCol index and renders that column with
moneyCell, which keeps the NULL -> dash meaning ("no published price") that
a bare toFixed would have destroyed.

The primary button's white label measured 2.52:1 against the dark theme's
brand blue (#6ba4fb), under the 4.5:1 WCAG AA floor for 13px text. The
light theme's #2563eb is dark enough for white (5.17:1), so the text
colour follows the theme through a new --on-brand token, carrying the same
pair in the no-light-dark() fallback. Dark text on the dark theme's brand
measures 7.55:1.

The project expander was the only control left at its 32px desktop size on
touch; it is now in the coarse-pointer rule with the others.

tests/test_ui_money.py guards all of it. It reads app.js to check the
wiring (a wrong column index fails silently -- the raw float just keeps
printing), then runs the real money/moneyCell/fillTable through Node
against a DOM stub and asserts on the text that would be displayed.
Reverting the moneyCol wiring fails 4 of its 5 tests.
